# Deliverables Tracker

What has been handed over, to whom, and whether it is still current.

| Deliverable | Type | Status | Link | Handed to | Last updated |
| :--- | :--- | :--- | :--- | :--- | :--- |
| [Name] | Flow / Spec / Prototype | Draft | [Figma / doc URL] | Name (role) | YYYY-MM-DD |

## Status Values

| Status | Meaning |
| :--- | :--- |
| `Draft` | In progress, not shown to anyone outside design |
| `In review` | Shared for feedback, not approved |
| `Handed off` | Delivered to engineering or the requester |
| `Stale` | Delivered, but a later decision has invalidated part of it |
| `Superseded` | Replaced by a newer deliverable |

## Rules

- **When a decision is marked `Superseded` in `design-decisions.md`, check this file.** A superseded decision usually leaves a `Stale` deliverable behind, and stale handoffs are how the wrong thing gets built.
- **Record who received it.** "Sent to the team" is not a handoff.
